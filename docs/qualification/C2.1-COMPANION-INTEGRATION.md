# C2.1 companion integration evidence

Date: 2026-09-12. This iteration delivers the Android/firmware integration and
reproducible software qualification. **Physical phone NFC and BLE qualification
remains open.** The connected ESP32-S3 boot check does not replace those tests.
GitHub #38, #39 and #48 are not closed by these results.

## Delivered behavior

- An installed companion resolves the Note4 NDEF MIME type from a cold launch
  and through foreground dispatch. Both paths consume the intent extras once.
  Ambiguous matching records, malformed payloads and unsupported peripheral
  addresses are rejected before connection or association.
- A tap selects its exact public/static-random BLE address. CDM discovery is
  filtered to that address; a different existing association cannot receive
  its proof. The proof stays in RAM, expires on a monotonic two-minute deadline,
  and is discarded after its first Hello attempt. Android still needs an
  approved association, Bluetooth permissions, the Note4 pairing window, a
  bonded encrypted link, notifications and protocol authorization.
- The selected approved Note4's queue loads before Bluetooth connects. Received
  reading positions remain visible offline; Resume queues a durable revision.
  Weather also uses the existing per-device queue. Phone time and timezone are
  sampled for each Hello, rather than replayed as stale durable timestamps.
- The GATT owner waits for both bond and subscription completion before Hello.
  Connection, discovery, subscription, pairing, handshake and writes have
  deadlines and deterministic cleanup. Automatic retries use monotonic backoff,
  stop after five retries, and require presence of the selected peer. Protocol,
  enrollment and store-recovery failures require an explicit retry. Another
  association disappearing cannot close the current link.
- The companion streams TXT/EPUB uploads through the existing local web API.
  It validates literal private IPv4 destinations, never follows redirects,
  keeps the access code only in memory, bounds source/response sizes, and does
  not retry writes with uncertain outcomes. A matching Wi-Fi route is used
  explicitly when Android keeps cellular as its Internet default. Android 37
  requests local-network permission; Android 26–30 retains explicit connection
  without calling the newer presence API.
- Phone-selected artwork is sampled to a bounded bitmap, oriented using EXIF,
  fitted onto a white 400×300 surface and dithered to a 15,011-byte PBM. A preview
  is available before sending. The firmware validates the fixed header and
  length while streaming, using the books partition's existing lease, staging,
  sync and no-overwrite commit. A replacement requires explicit removal of the
  saved picture. Sleep Cover > Phone Picture opens only the committed image,
  reads 50 bytes per row into the existing canvas, and retains the wake hint.
- Weather is requested explicitly for a chosen city from Open-Meteo, without
  location permission or background polling. The dashboard displays its cached
  place, Celsius temperature and condition while fresh; after six hours it
  returns to the daily line. A final cover is static, including its weather.

The Android emulator is `medlog_api35_lowmem`, API 35, x86_64. It supplies Android
framework, Keystore, lifecycle and socket behavior. Its NFC intent injection and
ADB-reversed HTTP connection are software tests, not antenna, BLE or WLAN evidence.
The new Android 37 permission path is compiled against SDK 37, not exercised by
this API 35 emulator. Physical phones on older/newer Android versions still need
compatibility testing.

## Reproduce

```bash
source tools/activate-dev-env.sh
bash tools/test-host.sh
bash tools/test-android-companion.sh
ZECTRIX_ANDROID_SERIAL=emulator-5554 bash tools/test-android-device.sh
ZECTRIX_TRANSFER_SANITIZE=1 bash tools/test-book-transfer.sh
ZECTRIX_DISPLAY_SANITIZE=1 bash tools/test-display-service.sh
bash tools/build-firmware.sh --profile full
bash tools/build-firmware.sh --profile minimal
uv run --no-project tools/compare-firmware-profiles.py build-full build-minimal \
  --output build-companion/profiles.json
# Optional connected ESP32-S3 boot verification:
bash tools/device-smoke-test.sh --profile full
```

`test-android-device.sh` installs the debug application and test APK on the
selected ADB target. Its temporary C++ HTTP fixture stores only test files;
its ADB reverse and server are removed on exit. The ordinary JVM task also
builds its own native fixtures, so cross-language coverage is not silently
skipped when running Gradle directly.

## Remaining physical checks

Use the installed debug APK, the current Full firmware and a real NFC-capable
Android phone. Keep the phone/firmware versions and observed outcomes together;
record public session/state events, never enrollment tokens or access codes.

- [ ] With the app stopped, touch Note4's antenna. Verify Android opens the app,
  the shown target matches the tapped device, CDM approves it and the user
  confirms the Note4 passkey. Repeat with a different Note4 already associated.
- [ ] Repeat in the foreground, after cancelling CDM, after token expiry and
  after an interrupted Hello. A consumed/replayed proof must not authorize;
  reconnect after a lost accepted HelloAck must use the persisted identity.
- [ ] Turn pages on Note4, verify the phone's received position, disconnect,
  queue Resume offline, kill/reopen the phone app and reconnect. Verify Note4
  offers Use phone position without navigating automatically or double-applying.
- [ ] Choose a city, reconnect and verify the Note4 clock/timezone and fresh
  dashboard weather. Check stale weather fallback with a valid clock.
- [ ] With cellular enabled, join the Note4 hotspot without Internet access.
  Send a TXT/EPUB and picture, finish, read the book and preview/sleep with Phone
  Picture. Repeat on a shared LAN and interrupt an upload before publication.
- [ ] Exercise background presence, permission denial/regrant, Bluetooth off/on,
  process death, association removal and Note4 Forget Phone/re-enrollment. For
  an intentional sync reset, clear both peers' sync relationship; do not erase
  just one side and expect previously acknowledged values to be reconstructed.

CrossPoint's cooperative paging, streamed transfer and row-based sleep image
rendering inform the bounded work here. Flipper's SceneManager/ViewPort design
informs keeping Choose/Preview and final display ownership on the foreground
owner. No upstream implementation or artwork was copied. See
[FIRMWARE_UI_STUDY.md](../FIRMWARE_UI_STUDY.md) for source references.
